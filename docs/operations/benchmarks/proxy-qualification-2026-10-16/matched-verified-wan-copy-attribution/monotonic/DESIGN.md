# Monotonic copy-attribution correction

This source-only derivative addresses the sole failure in preserved `../wan-copy-attribution-source/runs/tiny-copy-attribution-smoke-2`. The observer accumulated durations with `time.Time.Sub`, which uses Go's monotonic clock, but the validator compared those totals with `last_unix_ns - first_unix_ns`. Six single-call 32-byte POST response metrics differed by 1–10 ns across those clock domains. Both arms otherwise retained complete, correct evidence and remain formally rejected by their original summaries and attestations.

The correction adds two duration fields without changing the copy path:

- Each metric retains its first and last `time.Time` values and publishes `span_ns` as `last.Sub(first)`. Existing Unix timestamps remain available only for coarse ordering and correlation.
- The request entry retains its handler start `time.Time` and publishes `handler_elapsed_ns` as `returned.Sub(started)`. Existing handler Unix timestamps likewise remain coarse correlation stamps.

The validator requires nonnegative monotonic spans, `total_ns <= span_ns` for each metric, each metric span no greater than the monotonic handler duration, and the existing `read_total + write_total <= handler_elapsed_ns` and `read_total + inter_read_gap_total <= handler_elapsed_ns` relationships. Because upstream Read calls and inter-read gaps are consecutive intervals, it also requires the exact telescope `upstream_read.span_ns == upstream_read.total_ns + inter_read_gap.total_ns`. It no longer subtracts Unix timestamps to validate duration totals and no longer adds a monotonic stall duration to a Unix start timestamp. Stall Unix starts must still fall within the handler's coarse Unix interval. Histogram, top-eight, payload, error, wrapper, ReadFrom, sequence, scope, method, path, TLS, event, pool, reuse, rate, and lifecycle contracts are unchanged.

The observer still calls each underlying Read and Write exactly once with the original slice and return values. It adds two `time.Time` fields per fixed metric and one per fixed request record. No per-chunk allocation, lock, buffering, flush, method substitution, timeout, policy, pool, frame, or body-pump change is introduced. Inter-read gaps continue to overlap downstream Write and bookkeeping. POST remains response-copy-only.

Focused verification after source review should run the existing copy-attribution normal and race suites, including exact forwarding, partial `n+EOF`, errors, short writes, ReadFrom preservation, framing, bounded stores, allocation checks, and active publication. The extended fixed-summary test asserts exact monotonic metric span; the publication-barrier test requires a published monotonic handler duration. A regression rewrites the retained Unix fields after observation while leaving the `time.Time` values unchanged and verifies that exported metric span and handler duration still use their monotonic components. Validator contracts include a positive case where the Unix span is 10 ns shorter than the monotonic duration and negatives for `total_ns > span_ns`, a metric span beyond the handler duration, and a broken read/gap telescope.
