# Copy-attribution diagnostic integration notes

This observer is diagnostic only. Its throughput values are not qualification evidence. Upstream Read and downstream Write durations are compared separately with the monotonic public-handler elapsed time. Unix timestamps remain only for coarse ordering and correlation. Inter-read gaps include downstream Write time and bookkeeping, so they are never added to Read and Write as a third independent component. POST records cover only the 32-byte response copy; they do not attribute upload request-body time.

The inherited fixture's `agent_tunnels_initial` outer slice is a shallow copy. The peak tracker can later mutate nested lane values through shared backing storage. Nested initial lane fields therefore cannot establish starting lane credit and may reflect later maxima. High-water fields are sampled component by component at roughly 20 ms intervals and are not one coherent runtime state or a minimum-credit measurement. Final pools support conservation checks, not transient causal attribution. The detailed source map is `../current-wan-prep/COPY-TIMING-DECISION-MAP.md` and must travel with the evidence package.

The generated runner is reconstructed in three stages: the reviewed owned lifecycle runner plus the frozen WAN protocol patch must exactly equal the frozen WAN protocol runner; the copy-attribution runner patch must then exactly equal the frozen copy-attribution runner; and the one-line monotonic interpretation patch must exactly equal this derivative's generated runner. Each arm and the pair wrapper hash the helper module, all three runner inputs and generated runners, the frozen copy overlay, monotonic correction patches, build manifests, binaries, and TLS material before and after execution.

The inner analyzer and outer arm validator call the same immutable copy-record validation module. This is repeated enforcement, not independent implementation diversity. Independent review must use the raw per-row copy envelopes.
