# Scratch candidate: demand-triggered backed receive share

Core source is in `candidate/internal/tunnel`; `CORE.patch` changes only the common growing wrapper and adds the early helper, disabled hooks and focused tests. Tagged selector/ring and lifecycle sidecars are independently owned by `wan_policy_source`. These sources are not applied to production. Only source authoring and gofmt parsing have run; no tests/builds/validators/traffic.

## Exact trigger and ownership

For a tagged, explicitly configured aggregate wrapper below its existing ceiling, count only existing `Read` successes (`n>0 && err==nil`). The counter saturates at 512KiB and one lifetime attempt is consumed at the crossing, including ungrown-pool no-op. Closing, at-ceiling, legacy and unconfigured wrappers retain their original guard and do not count. No constructor or idle reset. This is opaque demand, not a trusted HTTP-body/bulk classifier: a hostile peer can supply 512KiB then stall.

While holding wrapper `c.mu`, the helper holds session growth-owner `g.mu`, matching ordinary lock order. It computes floor 4096(min(4MiB, current backed session limit/4, operator cap, negotiated allocation max)). It has no reserve callback invocation, slab allocation or session-window growth call. It uses existing checked allocation publication before byte-window publication and snapshots backing dimensions/lease cardinality before/after under the owner lock. Read/refund available/free credit is excluded from the invariant because it legitimately moves concurrently. Sessions may concurrently close; terminal/error snapshots are truthful, not evidence of a completed grant.

The ordinary estimator receives the successful consumed bytes once, with actual byte/allocation windows refreshed; its history and denial timer are unchanged. Off-arm observations never surface a new helper error: the original estimator decides Read errors. An already-at-ceiling wrapper preserves the old early return. Enabled allocation ErrStreamClosed is skipped only when exact sentinel and unchanged allocation limit establish the existing pre-mutation rejection; the wrapper does not then retry through ordinary estimation. Any allocation mutation plus error, and every byte-stage error, is returned without rollback/retry/release. The source limit mutates before enqueue, so an injected transport ErrStreamClosed after mutation is not mislabeled as a closed skip. Existing peer-FIN races are not made atomic: allocation and byte methods have separate locks; no stronger no-frame-after-concurrent-FIN promise is made.

The event is separate from ordinary demand-epoch history. `ThresholdProgressBytes` is capped progress, not an exact lifetime or crossing-read total. Start/completion hooks let the tagged owner prove no in-flight attempts at terminal. Stage names describe API progress, not confirmed remote acceptance. Error records contain only a fixed outcome category; the original error is returned unchanged. No normal-growth trace outcomes are added or relabeled.

For a grown pool of 8MiB the target is 2MiB (four times the initial 512KiB logical allocation); at 16MiB backing or more it is 4MiB (eight times initial). This removes up to two or three intermediate initial doubling steps, but only after 512KiB of successful consumption. It makes no new physical TCP congestion-window promise. At 80ms path RTT the idealized avoided sampling floor is about 160–240ms; saved cold rows take much longer because observation cadence and physical sender state interact. The screen must measure that interaction rather than attributing all saved read wait to byte-credit control.

## Actual lane and protocol boundary

`internal/agent/agent.go:1138` and `internal/server/server.go:1013` create this owner only for negotiated bulk-role sessions. `internal/server/public_routing.go:874` directs trusted health to lane 0; ordinary bulk rejects lane 0 preference. Agent wrappers are constructed before open-request parsing (`agent.go:1359`); max control frame 16KiB prevents a single legal open-request frame reaching 512KiB, but this does not establish application innocence. Reads include framing and any body bytes delivered through the wrapper. A retained HTTP stream's receive-wrapper counter persists across direction-cold reuse (seq 14); the opposite endpoint has independent receive state.

## Focused authored checks (not executed)

Eight common tests cover saturated once counter; target floors/all caps; no reserve or backing change on initial pool; fresh stream from grown backing and no shrink; owner/session/closed validity; one stalled 2MiB receiver with available 8MiB shared backing while another admitted stream transfers; allocation and byte transport ErrStreamClosed after mutation retaining leases until Session.Close. The single-stalled test claims progress only with spare shared credit, not progress of a fifth stream when four quarter-share stalls fill the pool.

Five tagged Read tests exercise zero/error-read gating, cumulative threshold, once no-op, closing/unconfigured guard, disabled observer error neutrality, closed skip with prior estimator history that would otherwise propose, fresh grown-pool grant and no idle re-arm after more backing. A private serial tagged test helper sets/restores diagnostic state; the exported selector stays startup-only. No tests use public policy input.

The additional four-stall test fills the 8MiB pool with four 2MiB shares, checks a fifth data write remains blocked, control Ping progresses and data recovers after draining one share. It asserts no new reservation. These are authored checks pending root-authorized execution, not passing evidence. Admission and global allocation safety stay unchanged, but the candidate deliberately bypasses ordinary two-sample demand qualification for up to 4MiB per eligible wrapper. Existing global backing stays bounded; fairness/occupancy duration can worsen. Performance authorization and the frozen off/on/off causal plan remain root-owned.
