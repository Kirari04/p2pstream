# Prospective private-namespace TCP idle/application-limited policy screen

**Source plan only.** Root owns implementation review, offline proof and any later runtime grant. This plan authorizes no commands, sysctl writes, tests, builds or traffic by its author. The completed C/R/C controller screen remains negative and immutable.

## Question and mechanism

Does changing only the private agent namespace's `net.ipv4.tcp_slow_start_after_idle` policy from 1 to 0 improve the entire fixed 256 MiB workload with CUBIC and the application path held constant?

The retained exact kernel source has two guards using this value: `tcp.h:1659–1670` guards `tcp_cwnd_restart` after idle, and `tcp_output.c:2165–2168` guards application-limited cwnd validation. Zero disables both reductions. It does not reset ssthresh or remove loss recovery. Name the treatment **idle/application-limited cwnd-validation policy**, not idle restart alone. The value is read through `sock_net(sk)->ipv4`; namespace isolation must be established before writing it.

The actual fixture places agent and origin in the same private network namespace. Consequently, its agent data lanes, control lane 0, agent-to-origin connections, origin endpoint sockets and local administrative sockets all receive the setting. Server and load reside outside it. This is a whole-private-namespace workload intervention, not a data-socket-only intervention. Source proof and role-to-namespace records must make that distinction explicit.

## Fixed experiment

* Three fresh arms in the predeclared order **1 / 0 / 1**; all TCP controller selectors stay explicitly CUBIC. Each arm has new complete endpoints and namespaces. Maximum 48 transfers, 16 per arm, one attempt per arm, no repeats or replacement cohorts.
* Keep all existing 256 MiB payloads, four download then four upload growth warmups, close-idle steps, exact pool-growth/quiescence predicates, and post-warmup D,U,D,U,U,D,D,U sequence. Keep H2, 80 ms configured RTT, shaping, CPU/cgroup/security/admission/application policies, 30-second idle timeout, accepted endpoint binaries/build receipt and existing capture limits unchanged.
* Set/read back the intended value in the exact private agent namespace **before origin, agent or any other relevant TCP socket is created there**. Do not toggle it after warmups: existing setup/terminal invariants require one value for the complete arm. Initial conditioning is part of treatment history, not a pretreatment matching covariate.
* Change no host/global setting, module parameter, route TCP metric, socket controller or other network policy. If the private namespace cannot be independently identified or the write/readback fails, stop without traffic and without fallback to a parent namespace. Namespace destruction supplies cleanup; no host restoration write should be necessary.

## Namespace proof schema and timing

Use a separate fixed-schema sidecar, bound into the new source/command freeze and prospective validator. An integer `expected_value` must come from the independent arm index (1,0,1), not from the observed field or public input. Include `schema_version`, `arm_index`, expected value, exact sysctl path, kernel release/source-binding identifiers, and fixed roles mapped to namespace device/inode identity. Records must be read from concrete owned processes/helpers; preserve process PID/start-tick and parent-ownership identity rather than relying on a namespace label.

1. **Before namespace mutation:** capture the host/outer-parent setting and namespace identity, and runner/server/load settings/identities. Establish the newly created agent/origin namespace identity is different from those protected namespaces. Capture its original value. The exact fixture role mapping is part of the proof: agent and origin share one namespace; deduplicate reads by namespace while retaining both role aliases. Do not pretend these are independent controls.
2. **After target setting, before first relevant socket:** capture the target value from the target helper and an independently resolved target-namespace readback. Capture protected namespace values again. Require target equals expected and all protected values remain exactly their prevalues. Retain the lifecycle ordering record proving this phase precedes origin and agent endpoint launch. For the control arms, perform the same explicit private setting/readback path with value 1.
3. **Endpoint binding:** join actual agent/origin/server/load endpoint process identities and their namespace identities to the pre-socket role map once endpoints exist. The prelaunch target-helper proof is not alone sufficient to prove where endpoints later ran.
4. **Post workload/terminal, before namespace teardown:** read target and protected values again using surviving owned namespace helpers; require target still equals expected and protected values equal their original values. Bind the post record to actual endpoint lifecycle identities and natural exits. Preserve final outer-parent readback after cleanup where the parent still exists. Missing or unjoinable evidence fails closed.

The existing `tcp_state.tcp_slow_start_after_idle` values are cached setup observations, not fresh per-sample sysctl reads. Existing agent instrumentation does separately read setup and terminal values and rejects change; its mature validators accept either integer 0 or 1 consistently. Require those original setup/terminal values and every cached owner value to equal the independently intended arm value, while preserving the originals unchanged. The new explicit namespace pre/post proof is necessary; cached repeated values alone cannot establish absence of mid-arm mutation. No claim of continuous monitoring is made.
