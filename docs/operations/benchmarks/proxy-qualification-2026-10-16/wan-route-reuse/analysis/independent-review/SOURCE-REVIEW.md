This is a source review, not a test result, throughput result or original qualification clearance. This reviewer ran no tests, builds, validators, namespaces or traffic.

The public-route factory now returns a reusable selector without acquiring a request claim or creating a retained pool entry. Each RoundTrip may prefer an idle same-route entry; selection and the in-flight increment happen under `tunnelMu -> pool.mu`. Both locks are released before HTTP I/O. The existing response/body tracker retains the claim until EOF, error or Close and uses its existing once-only completion. Entry retirement after a claim therefore follows the established draining path rather than abandoning the claim or inventing a second release mechanism. The transport pointer read outside the mutex is immutable after entry construction.

The lookup copies the complete security key and varies only the lane. It additionally requires the same agent-generation pointer, a live allowed public lane, a non-retired entry and transport, zero entry in-flight count and an advisory idle hint. Aggregate lane 0 remains excluded. Origin, TLS verification, certificate identity, target/environment identity and timeout cannot be crossed through the preference. Environment transports and trusted one-shot/control paths are unchanged. The nil-pool path retains ordinary direct construction.

Work is bounded by the fixed lane-slot array and at most four exact map lookups, with no scan through arbitrary route entries. Successful preference advances the existing round-robin cursor; slot arithmetic matches the current `transportLane` implementation, including its legacy array domain and aggregate control exclusion. Groups larger than four retain bounded preference and ordinary fallback; the implementation does not hardcode a four-lane deployment.

Cleanup and replacement release the tunnel lock before pool retirement; existing pool-held operations do not acquire that tunnel lock. No new lock inversion was found. Existing retirement may race a request already claimed, just as it can race the old RoundTrip increment; this change does not promise that already admitted requests are revoked synchronously. Existing admission queues, stream leases, one-shot fallback, memory bounds and control isolation remain the authority.

The idle hint and request-start timestamp are explicitly advisory. Expired origin connections can be dialed again by net/http with the normal capacity checks. Entry in-flight count is not whole physical-lane occupancy: other targets, draining entries and one-shot requests can share a lane. All-busy/no-eligible cases retain round robin without waiting or adding a per-lane concurrency cap. The fallback path can still share a busy entry; atomic exclusivity applies to choosing a preferred idle entry, not to all possible interleavings. Cold newly created entries have no reusable hint until response completion.

## Verification scope and required fixture migration

The authored tests cover simultaneous preferred claims in both transport modes, full-key/generation exclusion, control/closed/removed lanes, response ownership through EOF/error/Close/upgrade, retirement, uninvoked factories, the bounded preference window, cursor wrapping, all-busy fallback and real Yamux warmup retirement followed by reuse. These are authored contracts until root executes them. The synthetic protocol concurrency test proves selection and body ownership. A separate live four-lane fake-Yamux test holds four tunneled responses concurrently, verifies one open request/claim per lane, then releases and drains the exact small payloads. Another real transport test retains a stale idle hint while closing the actual socket, checks redial/reuse through the same wrapper, cancels a held body, checks claim release and verifies recovery. These distinguish hint safety from a fabricated guarantee of socket reuse.

Existing assumptions required deliberate migration. The pool separation test previously compared wrapper addresses and expected eager creation; it now executes requests and proves separate connections and pool entries. The real-agent primary-loss test previously used serial requests to populate every lane; explicit idle-pool retirement during its initial warmups preserves four-lane coverage, after which serial locality is expected, and its failure/reconnect/revocation assertions remain. Registry token-rotation and generation-cleanup fixtures now explicitly seed the same full-key pool constructor without I/O, preserving their ownership/invalidation assertions. The route-reconciliation test similarly compares actual seeded entries rather than newly allocated selector wrappers, retaining its unchanged-target identity and changed-target retirement checks. Include these affected existing tests in focused verification; none of these migrations just deletes a failing assertion.
